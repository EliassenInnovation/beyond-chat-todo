One overall chart is enough to illustrate variation in this small teaching app. For an agent performing critical tasks, measure those tasks separately and set much stricter failure criteria. A good overall average must not hide a critical failure.

Stable does not mean good enough. If a stable failure rate is unacceptable, improve the tools, prompts, model or application code. Review both the average and the variation, using comparable run sizes. Investigate serious individual failures even when the overall rate stays within the limits.

We have not adopted these limits as the reference for future runs. Review found real agent mistakes and apparent grading mistakes; those need to be addressed before accepting a reference for future comparisons.

How to use this example

We pulled examples from the recorded runs and present them below for a person to review. This checks both the agent and the judge: a person should agree that an outcome marked as a failure really failed, and that one marked as a success really succeeded.

  1. Read the request, starting state, actions and resulting state. Decide whether the agent did the right thing before looking at the recorded grade.
  2. Open the recorded result and compare it with your judgment. A false failure can send you fixing acceptable behavior; a false success can hide a real problem.
  3. Record your assessment and reason. If you disagree, determine whether the agent, the grading criteria or the judge needs to change.

Do this review even when the chart shows no unusual change. The chart summarizes rates; reading conversations reveals what those rates mean. Sample both successes and failures as part of ongoing review, rather than reading every interaction or only the failures.

The examples here include recorded passes and failures, deliberately selected for discussion. They are not a representative sample from which to estimate overall accuracy. Assistant review notes are suggestions, not human judgments. Your notes remain separate from the original grades and do not change the chart.

For ordinary changes: offline tests → focused evals → a full regression run when model behavior can change. Twenty full runs help estimate variation; they are not required after every edit. A new prompt, model, tool or grader starts a reviewed comparison period, not automatically new control limits.
